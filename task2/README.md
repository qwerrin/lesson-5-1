## 認証方式：サービスアカウントを使う（OAuth ではない）

**ここは課題1〜6と違う。** 理由を先に書く。

課題1〜6（`lesson-4-3-2`）は OAuth 2.0 で、同意画面を開いて `token.json` を取る方式だった。
共有部品 `common/google_auth.py` もそれ用で、このリポジトリにも移植済み。
**しかし課題2では使わない。**

Google の公式ドキュメントにこう書いてある:

> A Google Cloud Platform project with an OAuth consent screen configured for an
> external user type and a publishing status of "Testing" is issued a refresh token
> expiring in **7 days**
>
> — <https://developers.google.com/identity/protocols/oauth2#expiration>（2026-09-06 確認）

`lesson-4-3-2` の同意画面は **User Type = 外部**、公開ステータスは**「テスト」**のまま。
つまり **リフレッシュトークンは7日で失効する**。

課題1〜6 は**手で叩く単発スクリプト**だったので、失効しても同意し直せば済んだ。
**課題2は「定期的に」動かすことがゴールに書かれている。**
7日目に動かなくなり、**定期実行なので誰も見ていない**——
`DESIGN.md` の 4-⑨（IPが変わると静かに死ぬ）とまったく同じ形の穴になる。

### 採らなかった案と理由

| 案 | なぜ採らないか |
|---|---|
| OAuth のまま、公開ステータスを「本番環境」に切り替える | `spreadsheets` は機密スコープなので、本番公開に**Google の審査**が要る可能性がある。課題の期間に対して重い |
| OAuth のまま、7日ごとに手で同意し直す | 「**定期的に**取得し反映するプロトタイプ」というゴールを、運用で崩している |
| **サービスアカウント** | ブラウザの同意を経由しないので**リフレッシュトークンの7日制限が無い**。サーバ側の定期処理はこれが標準 |

> **`common/google_auth.py` は課題2では使わない。** 移植が無駄になったわけではない
> （共有部品として残り、テスト14件も回り続ける）が、**使わないと決めた理由をここに書いておく**。
> 「置いてあるから使う」で選ぶと、7日で死ぬ設計をそのまま通してしまう。

## 先に済ませること（Google Cloud 側・手作業）

**ここは AI に任せられない。** 資格情報の入力とアクセス許可はアカウント本人の操作でしかできない。

### 1. プロジェクトを選ぶ

[Google Cloud コンソール](https://console.cloud.google.com/) を開く。
`lesson-4-3-2` で作ったプロジェクトを**そのまま使ってよい**（新規でも可）。

### 2. Google Sheets API を有効にする

「API とサービス」→「ライブラリ」→ **Google Sheets API** を検索 →「有効にする」。

**課題1〜6 で有効にした Drive / Docs / Gmail とは別の API。**
有効にしていないと、認証が通っても呼び出しが `403` で落ちる。
有効化の反映に数分かかることがあるので、直後の `403` は少し待ってから判断する。

### 3. サービスアカウントを作る

「API とサービス」→「認証情報」→「認証情報を作成」→ **サービスアカウント**

- 名前は任意（例: `sheet-writer`）
- **ロールは付けなくてよい。** ここで付ける IAM ロールは Google Cloud の資源に対する権限で、
  スプレッドシートへのアクセスとは**別の仕組み**。シート側の共有設定で許可する（手順5）

作成後、そのサービスアカウントの詳細 →「キー」→「鍵を追加」→「新しい鍵を作成」→ **JSON**。
ダウンロードされた JSON を**リポジトリのルート**に置く。

```
lesson-5-1/service-account.json
```

### 4. サービスアカウントのメールアドレスを控える

JSON の中の `client_email` にある。形はこう:

```
<名前>@<プロジェクトID>.iam.gserviceaccount.com
```

**これはメールアドレスの形をしているが、人間の宛先ではない。** 次の手順で使う。

### 5. 書き込み先のスプレッドシートを作って共有する

1. [Google スプレッドシート](https://sheets.google.com/) で**新規作成**する
2. 名前を付ける（例: `楽天 価格ウォッチャー`）
3. **右上の「共有」を押し、手順4のメールアドレスを「編集者」として追加する**
   - 通知メールのチェックは外してよい（宛先が人間ではないため）
   - **ここを飛ばすと、認証は通るのに書き込みだけ `403` で落ちる。**
     権限（API の有効化）と所属（シートの共有）は別物で、
     課題1で Slack の「スコープはあるがチャンネルに居ない」で踏んだのと同じ形
4. URL から**スプレッドシートIDを控える**

```
https://docs.google.com/spreadsheets/d/<ここがID>/edit#gid=0
```

### 6. `.env` に足す

```
GOOGLE_SHEET_ID=（手順5のID）
GOOGLE_SERVICE_ACCOUNT_FILE=service-account.json
```

**楽天の2つ（`RAKUTEN_APPLICATION_ID` / `RAKUTEN_ACCESS_KEY`）は登録済み。**
値の意味と取り方は [`.env.example`](../.env.example) に書いてある。

## 実機で確かめたこと（2026-09-08）

**2回流した。** 1回目で書き、2回目で「読み戻して比べられるか」を確かめている。

```
【1回目】                      【2回目】
見出し     書いた               見出し     一致
取得       3 件 / 失敗 0 件      取得       3 件 / 失敗 0 件
書き込み   送った 3 / 入った 3    書き込み   送った 3 / 入った 3
比較できず 3 件（初回 3）        （比較できずの行が出ない＝3件とも比較できた）
```

**2回目で「比較できず」が消えたことが、この課題のいちばん重要な証拠。**
書いた値が、読み戻したときに**同じ意味で使える形のまま**だったという意味になる:

```
RAW で書く → UNFORMATTED_VALUE で読む → 時刻が解釈できる → 価格が int → 比較が成立
```

どれか1つでも外れると、**エラーは1つも出ないまま**全商品が「比較できない」になり、
値下がりの通知が永久に鳴らない。**「書けた」は「読み戻せる」の証拠にならない。**

### 3回目：別の資格情報で読み直して照合した（2026-09-09）

```
書き込み   送った 3 行 / 入った 3 行
照合       3 行 × 45 セルを比べました      ← 数字が無い「一致」は出さない
行数       前 7 → 後 10                   ← 7 + 3 = 10。既存の行は無事
不一致     0 セル
```

**「一致」は「比べた」の証拠にならない。** 0行と0行を比べれば必ず一致するので、
`verify_sheet.py` は**比べた行数とセル数を必ず出し、0件を成功にしない**。
読み直しは**読み取り専用のスコープで別に認証**する——書いたのと同じもので読むと、
確かめる経路が書く経路と1本になり、その1本が壊れたとき確認も一緒に壊れる。

`行数 前 7 → 後 10` は、**追記が既存の行を上書きしていないこと**の確認。
上書きされた古い行は、今回書いた行の検査を全部通ってしまう。

> **照合器を壊す検査で4か所が素通りした。** そのうち1つは、報告に
> 「不一致 0 セル」という別の行があるせいで、「比べた数」を消しても
> `"セル" in text` が通ってしまうというもの——**この README に自分で書いた
> 「部分一致は弱い」を、照合器のテストで自分がやっていた。**
> 期待値を丸ごと固定して塞いだ。

### 実物で「鳴らない検査」を1つ見つけた（2026-09-09）

点検の出力に `列が短い 0 行` とあった。**この数は必ず 0 になる**——
読む側が幅をそろえてから数えていたので、短い行はもう存在しなかった。

補う**前**に数えるように直したら `末尾が落ちた行 6 行` と出た。
末尾の空欄が返ってこないこと（5-Q）が、**毎回起きている**という記録になる。

**0 が出ている検査は、通っているのか、見ていないのか分からない。**

### 書いてからでないと出なかった穴

読み戻して型を数えたら、**列数がそろっていなかった**。

書いた行は15列。しかし取得できた行の末尾（`理由`）は空なので、**14列で返る**。
公式にこう書いてある:

> For output, empty trailing rows and columns will not be included.
> — <https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values>（2026-09-08 確認）

設計の段階（`DESIGN.md` の 5-K〜5-P）では出せなかった。読めば分かる記述だが、
**どの列が末尾に来るかは実装を書いて初めて決まる**ため。
`DESIGN.md` に 5-Q として足し、`read_rows` に幅を渡して補うようにした。

> このとき `diff` は**たまたま**壊れていなかった——「列が足りない行で落ちない」
> ガードを別の理由（人がシートの列を消す）で先に入れていたため。
> **偶然守れていた**ので、実物と同じ形（末尾が落ちた行）のテストを2件足して固定した。

## 動かす

```powershell
.venv\Scripts\python.exe task2\verify_sheet.py
.venv\Scripts\python.exe task2\to_sheet.py --dry-run
.venv\Scripts\python.exe task2\to_sheet.py
```

**`--dry-run` は「何もしない」ではない。** シートには1行も書かない（見出しも作らない）が、
**楽天 API には投げる**＝QPS を消費する。オプション名は「何をしないか」までしか言っていないので、
実行結果にもその1行を出している。

終了コードで区別する:

| | |
|---|---|
| 0 | 全部取れて、全部書けた |
| 1 | 書き込みが足りない（送った行数と入った行数が違う） |
| 2 | 取れなかった商品がある（書き込みは足りている） |

**0 以外を返すことが目的ではない。** 定期実行では誰も画面を見ていないので、
「何が起きたか」を数字の形で残すのが目的。

課題2のテストは **232 件**（`common/sheets_client` の 47 件を含む合計は 279 件）、
わざと壊す検査は **92 か所すべて kill・素通り 0・置換先なし 0**。
リポジトリ全体では **648 件**が通る（課題1の分は1件も壊れていない）。

> **素通りは実際に出た。** 2026-09-08 に書き込み層を足したとき、74 か所のうち **3 か所が素通り**した——
> ①見出しの範囲を `A1:D1` と固定しても、テストの列数がちょうど4で一致してしまう
> ②落とした重複を途中で捨てても、`load_watchlist` の検査だけでは気づけない
> ③`expected_width` を渡さなくても、`transform` の作る行はいつも長さが揃うので差が出ない。
> **3つとも「テストは緑・実装は壊れている」**。テストを5件足して塞いだ。

> **「テストが通った」を結論にしない。** `mutate.py` が実装を1か所ずつ壊して、
> テストが落ちることを確かめる。**14 か所のうち1つは最初 素通りした**
> ——「両方の語が残っている」という部分一致の確認では、
> 改行を空白ではなく**削除**する実装を見分けられなかった。期待値を丸ごと固定して塞いだ。
