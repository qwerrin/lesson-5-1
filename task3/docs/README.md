## 対にして読むもの

課題2 の講評（`../DESIGN.md` 11章）が求めているのは
**ソース側と出力側を対で見せること**と、**件数を絵に入れること**。

| 対 | 言えること |
|---|---|
| **01（8件中2件）** ＋ 議事録の実行画面（「検査: 問題なし」） | *一貫性の検査は、正しさの検査ではない* |
| **01（ソース側）** ＋ **03（出力側）** | 同じ `verify` でも**見ている相手が違う** |
| **02** ＋ **04** | 書けること と、二度書かないこと |
| **07（実行画面）** ＋ **08（届いた実物）** | **送ったことの証跡と、届いたものは別**。LINE には bot が送った本文を読み返す API が無いので、`messageId` と通数の増分は「送信が起きた」までしか言わない |

## 撮っていないもの

**01〜03（音声生成・文字起こし・議事録作成）の実行画面は撮っていない。**
文字起こしと議事録は呼ぶたびに課金が乗り、しかも**実行ごとに結果が揺れる**
（決定事項が 2件／3件 と変わった実測がある）ので、撮り直すと
上の6枚と辻褄が合わなくなる。中間成果物は `../meeting/` に残してある:

- `transcript.txt` — 文字起こし（101発言・3話者）
- `minutes.txt` / `minutes.json` — 議事録（本文と型）
- `script.md` — 台本と正解データ（**照合の物差し**）

## 撮り方

`tools/shots.py` を引数なしで呼ぶと手順が出る。**枠を短くしてから撮る**
——`cls` が消すのは履歴だけで、プロンプトとタイトルバーは毎回ホームのパスを出す
（`../DESIGN.md` 17章）。
